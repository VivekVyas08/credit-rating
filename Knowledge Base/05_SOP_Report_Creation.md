# SOP — Rating Report Creation (BINDING, v2)

> **⚑ ONE FLOW FOR ALL THREE AGENCIES:** follow **`UNIFIED_RATING_GUIDE.md`** at the project root — it merges ICRA + CRISIL + CareEdge into a single 19-step process with a stop-and-ask gate at every step. This file remains as LOOKUP DATA / deeper detail only.

*Rewritten July 2026 after the HAL exercise. The v1 failure was not just arithmetic — it was PHILOSOPHY: the reference report was used as a data source and anchor, instead of forming an independent view from company documents and methodology. This version makes independent analysis structurally unavoidable. Every step produces evidence; a step without visible output was not done.*

---

## THE OPERATING PRINCIPLE

**Reference reports teach the craft; company documents supply the facts; the methodology supplies the framework; the analyst supplies the judgment.**
The prior ICRA report on the same company is consulted ONLY after my own view is formed — as a consistency check and for instrument/mandate context — never as an input to the analysis.

**THE PRE-DRAFT GATE (added after ITC + JSW Steel, both of which failed the same way).** Before a single line of the report is written, EVERY uploaded document must have been read one by one, in full, and logged in a **Document Read Log** (Step 1b): each annual report, each quarterly result/presentation, each broker/sector note, the term sheets. Two errors keep recurring and are now structurally blocked:
- **Copying the anchor** — its "stable tax regime" line (ITC, obsolete post GST 2.0) and its Annexure I / summary table (JSW, wrong NCD amount + phantom CP). The anchor is craft-only; re-derive every fact and forward claim from the company's own current documents.
- **"Instrument details not available"** — false for any listed issuer. Annexure I is built by grepping the annual report for `INE`-codes, "Non-Convertible Debenture", "ISIN" and "Commercial Paper" (Step 7b); the Corporate Governance report, borrowings note and rating note carry the full instrument schedule and every CRA's rating.
Verify company-disclosed figures (leverage caps, net debt, market share, capacity) against the company's OWN document, not a broker's paraphrase.

**THE RESPONSE PROTOCOL (CLAUDE.md §10 — added Jul 2026, user-directed; applies to EVERY response, not only deliverables).** (1) Identify and strictly follow the governing rule/step; deviations are declared, never silent. (2) Self-audit before sending: re-read the drafted response claim-by-claim — traced or assumed? do the numbers reconcile? what would falsify it? Fix or flag BEFORE the user has to catch it. (3) Every material conclusion ships with its data trail inline: *conclusion — figure(s) — source (document + note/section, or script output)*. Estimates and judgment calls are labelled as such. A response without its evidence is not complete.

## PHASE 1 — LEARN & SCOPE (before touching the numbers)

**Step 1. Inventory the inputs.**
List every document received: period covered, audited/unaudited, standalone/consolidated. List explicitly what is MISSING and how each gap is handled:
- Sanction letters / rating mandate (rated amounts) → ASK THE USER. Never silently inherit from an old rationale.
- Latest FY/interim results → ask, or disclose the data cutoff.
- Sector-assumptions document (per Vivek's protocol) → ask if not shared.
Evidence: the inventory table shown to the user.

**Step 2. Route to methodology.**
Entity type + sector → methodology files via 01_Methodology_Index, cross-checked against 02_Sector_Routing_Map (peers, not the company itself). Corporates = 960 + sector methodology; banks = 929; NBFCs = 1003; infra SPVs = asset methodology + 938/1021 as applicable.
Evidence: named files and the routing logic.

**Step 3. Read the methodology IN FULL, at rating time.**
The current sector methodology + the master framework + relevant cross-cutting approaches (934 consolidation, 963/962 support, 1014 liquidity, 995/998 instrument features). KB summaries are for routing only.
Evidence: the specific rating factors from the methodology that will structure the analysis (listed before analysis starts).

**Step 4. Learn the sector's rationale craft — from PEER reports, not the company's own.**
Read 2-3 reference reports of close peers in the same sector (via 02 routing map + 06 library). Extract: which metrics the narrative quotes, the driver taxonomy, calibration (what earns AAA vs A in this sector), liquidity-argument style, sensitivity patterns. Update 06_Rationale_Construction_Library if the sector isn't covered yet.
**Extract ZERO facts from these reports.** The company's own prior report is NOT read in this phase.
Evidence: sector-craft notes (metrics list, driver themes, calibration observations).

## PHASE 2 — INDEPENDENT DATA WORK (company documents ONLY)

**Step 5. Extract all data into a computation script** from the company's audited statements — every line item needed, units stated at extraction (lakh/crore), converted once, in code. Both consolidated and standalone captured where they exist; the analytical basis chosen and justified per 934. **THEN generate `Companies/<slug>/<Co>_Financial_Spreads.xlsx` FROM the script** (user directive 17-Jul-2026): tabs = Extraction (line items + AR note references) · RatioSuite · TieOut (PASS/FAIL). Script = source of truth (R6); Excel = review/feed layer, literal values, render-verified. The Step-12 model and Step-12b scorecard take their historicals from this workbook — no re-typing.

**Step 6. Compute the FULL 927 ratio suite in code** — profitability (OPM, NPM, RoCE), leverage (gearing, TOL/TNW, TD/OPBDIT, NCA/TD), coverage (interest cover, DSCR), working capital (debtor/inventory/payable days, cycle, current ratio, WC intensity), cash flows (FFO, CFO, RCF, FCF) — 3-5 year trend where documents allow. Not-meaningful ratios marked n/m with reason.

**Step 7. Extract and verify every qualitative fact from the company's documents**: shareholding, board composition, order book and named contracts, segments and customer concentration (computed from segment/export notes, not asserted), contingent liabilities and their movement, capex plans and funding, litigation, auditor observations (KAMs, qualifications), subsidiaries/JVs with stakes.

**Step 8. Materiality sweep.** Go through the document sections the analysis hasn't touched (notes, auditor report, directors' report, BRSR) hunting for credit-relevant items nobody asked about: settlements, guarantees, related-party movements, governance gaps, one-offs in P&L. Each finding gets a written include/exclude decision with reason.

**Step 9. Save the workpaper** (`<Company>_Ratio_Workpaper_<date>.md`): computed suite, trend commentary, qualitative fact register with source locations, materiality decisions, caveats.

## PHASE 3 — INDEPENDENT ANALYSIS & RATING VIEW

**Step 10. Apply the methodology framework factor by factor** — Industry risk → Business risk (competitive position, diversification, asset quality) → Financial risk (validated against business risk per 960) → Management/governance → Other elements (parentage/support per 963, project risk, forex, contingent liabilities, event risk) → ESG. Score each factor against the methodology's own descriptors and the sector calibration learned in Step 4.

**Step 11. Liquidity analysis per 1014** — sources vs claims arithmetic over ~12 months; descriptor (Superior/Strong/Adequate/Stretched/Poor) is the CONCLUSION of the arithmetic.

**Step 12. Projections** — base case from historicals + sector-assumptions document + AR guidance; stress case sensitising the methodology's named variables. Every assumption tabled with source (sector doc / historical / AR / judgment).

**Step 13. Form MY rating view** — standalone assessment → support notching → instrument adjustments → LT/ST mapping check (04_Core empirical table) → outlook per 110. Written BEFORE looking at the prior rating.

**Step 14. ONLY NOW open the company's prior ICRA report.** Compare: rating, outlook, drivers, liquidity descriptor, figures. Every divergence explained — either my analysis found something the anchor missed/postdates, or I correct my view with reason. Instrument/mandate details from the anchor are flagged as REQUIRING USER CONFIRMATION, not adopted.
Evidence: divergence table.

**Step 15. STOP — user sign-off.** Present: input gaps and how handled, assumptions table, stress result, my independent rating view, the divergence table vs the prior report, rated amounts NEEDING confirmation, all judgment calls. No drafting before approval.

## PHASE 4 — DRAFTING

**Step 16. Draft per 03_Report_Template** in the correct variant, using the sector narrative conventions from Step 4. Every number copied from the workpaper output; every qualitative claim traceable to the fact register. Nothing enters from the anchor report except user-confirmed mandate details and rating history.

**Step 17. Re-verify the final draft**: re-run the script against every number appearing in the draft text (drift check); confirm driver-sensitivity symmetry; liquidity descriptor vs arithmetic; LT/ST consistency; section completeness.

## PHASE 5 — DELIVERY & LEARNING

**Step 18. Deliver report + workpaper together**, with data-cutoff limitation, computation-basis note, and the caveat list inside the report itself.

**Step 19. Log lessons the same day** — any mistake found at any stage goes into this SOP, the 06 library, and memory.

## THE SEVEN RULES

1. **Reference reports are teachers, not sources.** Zero facts flow from them into a new report (user-confirmed mandate details and rating history excepted).
2. **My view forms before the anchor is opened.** Anchor comparison is Step 14, never Step 1.
3. **Nothing is verified until computed or traced to the company's documents.** "It matches the old report" is not verification.
4. **Verification before drafting; re-verification after drafting.**
5. **Missing inputs are asked for, not improvised** — rated amounts, utilisation, latest results.
6. **Every judgment, divergence and limitation is disclosed in the deliverable itself.**
7. **Every step has visible output. No output = not done. "Mostly yes" does not exist.**

- **[Scorecard back-test, 18-Jul-2026] The anchor's downward bias was the composite→grade MAP, not the financial bands.** Back-tested `Rating_Scorecard.xlsx` on 396 ICRA-rated issuers (379 corporate + 17 financial) + the JSW/IIFL fully-scored cases. Baseline anchor ran **+2.13 notches too low** systematically (reproducing JSW A−-vs-AA, IIFL A+-vs-AA). Root cause: the linear map `(C−1)/5×16` is too harsh in the investment-grade zone (a strong composite ~2 → AA−/A+ instead of AA). **Financial bands are NOT tunable to the target** — recalibrating them to the rated population *raises* thresholds and worsens the bias (bands, map, prior are entangled). Fix = a **range-preserving power softening `16·((C−1)/5)^1.4`** (endpoints AAA/C preserved; bias→+0.13; validated on both real cases — IIFL 2.21→AA, JSW 2.99→A+). Also added a **`Ref_Qualitative`** 1–6 rubric and mandatory **support-notch discipline** (the neutral scorecard under-rates PSU/support-driven names 2–3 notches — leaving the notch at 0 was a direct cause of the misses). **Key limit: ±1/80% is unreachable from financials alone** (Spearman(financial score, grade)=0.32; isotonic ceiling 47% within-1) — the agency grade is majority-qualitative. The anchor is therefore a **zero-biased ±2 screening band**, never a point rating; divergence beyond ±2 (or any for AA+/AAA and BB-and-below) is committee-resolved. Full record: `Scorecard_Backtest_Report_18Jul2026.md`. Master stays formula-driven (Excel recalcs on open); verified via the `formulas` engine (READ-ONLY — never `.write()`).
